# 규칙

- 너(Claude)의 코드 네임은 최운겸이다.
- 답변은 예외 없이 무조건 한국어로 한다.

## 작업 절차

- 사용자가 프롬프트로 작업을 요청하면, 작업을 시작하기 전에 항상 해당 작업의 todo list를 먼저 작성해 사용자에게 보고한다.
- 사용자가 todo list를 읽고 승인하기 전에는 작업을 시작하지 않는다. 사용자가 수정을 요청하면 todo list를 고쳐 다시 보고한다.
- 작업을 마친 뒤 폴더나 파일이 추가되었다면, 마지막으로 파일과 폴더를 Claude Code가 가장 잘 인식할 수 있는 구조로 정리한다(아래 "프로젝트 구조" 참고). 구조가 바뀌었으면 그 섹션도 갱신한다. 이 정리 작업은 모든 todo list의 마지막 항목으로 넣어, 나머지 작업과 함께 승인받는다.

## 프로젝트 구조

```
agent_09/
├── CLAUDE.md      # 프로젝트 규칙 (이 파일)
├── research/      # 자료조사 결과 (.md, 영문)
├── report/        # 최종 보고서 (.docx)
├── scripts/       # 보고서 생성 스크립트 (Node.js, `docx` 패키지)
└── translate/     # .md 파일의 한국어 번역본 (같은 상대 경로, `_ko` 접미사)
```

- 새 조사 노트는 `research/`에, 최종 보고서는 `report/`에 저장한다. 결과물을 프로젝트 루트에 두지 않는다.
- 기존 결과물은 덮어쓰지 않는다. 날짜 접미사를 붙인 새 파일을 만든다 (예: `_20261004`).
- 보고서를 다시 만들 때는 `scripts/` 안에서 `npm install`을 실행한 뒤 `npm run report`를 실행한다.

## 마크다운 파일과 번역본

- 모든 `.md` 파일은 영어로 작성한다.
- `.md` 파일을 만들 때마다 한국어 번역본을 `translate/`에 저장한다. 원본과 같은 상대 경로를 유지하고 파일 이름 끝에 `_ko`를 붙인다 (예: `docs/setup.md` → `translate/docs/setup_ko.md`). `translate/` 안의 파일은 다시 번역하지 않는다.
- 번역본 이름을 `CLAUDE.md`로 짓지 않는다. 하위 폴더의 `CLAUDE.md`는 추가 지침 파일로 읽히기 때문이다.
- `.md` 파일이 수정되면 무엇이 바뀌었는지 확인하고 같은 변경을 번역본에도 반영한다.
- `.md` 파일이 삭제되면 번역본도 삭제한다. 이름이 바뀌거나 위치가 옮겨지면 번역본도 똑같이 이름을 바꾸거나 옮긴다.
